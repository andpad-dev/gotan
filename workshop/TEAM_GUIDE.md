# チームでの進め方

このページは、4 人程度の班が一人の調査待ちにならず、別々に集めた証拠を一つの説明へまとめるためのガイドです。
時間制ワークショップでは、シナリオの全設問を順番に解き切ることより、調査ルートを再現可能な形で残すことを優先します。

## テーマ選択までの 5 分

1. 名前、Go 歴、今日気になることを一人 20〜30 秒で共有します。
2. [シナリオ一覧](README.md#シナリオ一覧) からテーマを一つ選びます。

探索ワークが始まったら、最初の 3 分でシナリオ本文を全員で読み、「何を調べれば完了か」を一文で言い直します。
続けて調査担当と最後のまとめを書く人を決めます。まとめ役も調査に参加し、終盤に各コメントをつなぎます。

## 調査を並行に分ける

設問番号の分担に加えて、異なる種類の証拠を同時に集めます。シナリオに合うものを 2〜4 個選んでください。

| 担当 | 調べること | 班へ返すもの |
| --- | --- | --- |
| 観測・実験 | Playground やコマンドで、シナリオ本文の出力・panic・エラーを再現する | コード共有 URL、版、コマンド、実際の出力 |
| API・仕様 | go.dev や pkg.go.dev から契約・用語・例外条件を探す | セクション名、確認した文の要約、次のリンク |
| 実装・履歴 | バージョン付きソース、リリースノート、Proposal、Issue をたどる | 変更理由、版の差、事実と推測の区別 |
| 反例・レビュー | 条件や入力を変え、別担当の結論がどこまで成り立つか確かめる | 反例、適用条件、未解決点 |

初級は「実験」と「ドキュメント」の 2 組に分けます。中級は設問と証拠種別を組み合わせた 3 組、上級は「現行仕様」「実装」「歴史」の 3 組が目安です。
途中で担当を入れ替え、同じ人だけがソースやコマンドを操作し続けないようにします。

## 40 分の使い方

| 経過 | やること |
| --- | --- |
| 0〜3 分 | 問いを一文にまとめる。担当とまとめ役を決める |
| 3〜18 分 | 各担当が並行に調査。その場で Issue に記録する |
| 18〜25 分 | 一人ずつ発見と次の疑問を共有。別担当が根拠を確認する |
| 25〜30 分 | 足りない証拠・反例だけを追加調査する |
| 30〜40 分 | まとめ役を中心に、全員で調査ルートと発表文を作る |

残り 10 分の合図まで各自が黙って調べ続けないでください。18 分前後で一度合流すると、同じページを重複して読むことや、
一人だけが答えを抱えたまま終わることを防げます。

## ヒントと答え

- 時間制ワークショップでは、ヒントを最初から開いて構いません。担当を分ける検索語や一次情報の入口として使います。
- 自習では、ヒントを閉じて 5 分または異なる調査 2 回を試してから開くと、探索自体を楽しめます。
- 答えを開いた場合も、結論をコピーせず、記載された調査ルートを別担当が実際にたどって確認します。

## Issue に残すコメント

各自が調査するたび、次を一つのコメントとして残します。URL だけのコメントにはしません。

```text
- 担当した問い:
- 出発点:
- 操作・検索語:
- 見た場所: <URLとセクション名>
- 分かったこと:
- 次の疑問・未確認:
```

Go Playground では **Share** を押して共有 URL を作り、コード、表示された Go のバージョン、実際の出力を同じコメントに入れます。

終盤は、まとめ役が各自のコメントを並べ替え、全員で次を確認します。

```text
## 発表まとめ
- 調べたテーマ:
- 最初の観測:
- 調査ルート: <出発点 → 検索語/リンク → 一次情報 → 実測>
- 分かったこと:
- まだ分からないこと:
- 一番の発見:
```

まとめ役が一人で結論を作るのではなく、各担当が自分の根拠と要約が正しいかを最後に確認してください。
