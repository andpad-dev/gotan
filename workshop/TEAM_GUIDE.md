# チームでの進め方

シナリオは**班全体で1つ**に取り組み、その中の**設問をペアで分担**します。4人なら2人ずつの2組です。

時間制のワークショップでは、全設問を解き切ることより、調査ルートを再現できる形で残すことを優先します。

## テーマ選択までの5分

1. 最初の3分で自己紹介をします。名前、Go 歴、今日気になることを一人ずつ。
2. 残りで [シナリオ一覧](SCENARIOS.md) からテーマを1つ選び、班の Issue に宣言します。

## 探索ワークの最初の3分

入り口と分担を決めます。

1. 班全体で、シナリオの **調査の入り口** かカテゴリの README を開き、どの一次情報から入るかを決めます。
2. 2人ずつのペアに分かれ、設問を分担します。設問が2つならペアごとに1つ、3つ以上なら前半・後半で分けます。
3. 最後に全体をまとめる人を1人決めます。まとめ役も調査に参加します。

設問の数がペアに合わないときは、片方のペアが1問多く持つより、**1問を2ペアで別々の入口から攻める**ほうが実りがあります。
片方は Playground で動かし、もう片方は仕様を読む、という分け方です。

## 45分の使い方

| 経過 | やること |
| --- | --- |
| 0〜3分 | 班で入り口を決め、設問をペアで分担する |
| 3〜25分 | ペアごとに調査。その場で Issue に記録する |
| 25分（残り20分） | 答えを開いてよい合図。まだ手がかりがなければここで開く |
| 25〜35分 | ペアどうしで発見を持ち寄り、一つのコメントにまとめる |
| 35〜45分（残り10分） | まとめ役を中心に、発表まとめを書く |

ペアの中で1人だけが操作し続けないよう、途中でキーボードを交代してください。

## ヒントと答え

- **ヒントは最初から開いて構いません。** 検索語や一次情報の入口として使います。
- **答えも開いて構いません。** 残り20分でファシリテーターから声をかけます。結論をコピーせず、書かれている調査ルートを実際にたどって確認します。
- 自習でやるときは、ヒントを閉じて5分または異なる調査を2回試してから開くと、探索そのものを楽しめます。

**全設問を解き切る必要はありません。** 1問を確実に深掘りするほうが、今日の目的には合っています。

## Issue に残すコメント

各自が調べるたび、次を1つのコメントとして残します。URL だけのコメントにはしません。

```text
- 担当した問い:
- 出発点:
- 操作・検索語:
- 見た場所: <URLとセクション名>
- 分かったこと:
- 次の疑問・未確認:
```

Go Playground では **Share** を押して共有 URL を作り、コード、表示された Go のバージョン、実際の出力を同じコメントに入れます。

終盤は、まとめ役が各自のコメントを並べ替え、全員で次を確認します。

```text
## 発表まとめ
- 調べたテーマ:
- 最初の観測:
- 調査ルート: <出発点 → 検索語/リンク → 一次情報 → 実測>
- 分かったこと:
- まだ分からないこと:
- 一番の発見:
```

まとめ役が一人で結論を作るのではなく、各ペアが自分の根拠と要約が正しいかを最後に確認してください。
