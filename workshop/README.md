## ワークショップの目的

みなさん、こんなお悩み、ありませんか？

- 先輩やLLMの書いたGoのコードがよく分からないので調査したい
- Goに関する質問をLLMにしたがLLMの回答が正しいのかどうか判断が付かない
- 他の言語にはあるのにGoにはない、もしくはGo特有の機能が何故あるのか議論の背景を深堀りしたい
- 次回以降のGo Conferenceへ質の高いProposalを出して登壇を目指したい
- Goのコントリビューターを目指したい！

このワークショップに参加されている方であれば、少なからずGoについてもっと知りたいと思ってくださっていると思います。

こんな課題が発生した時に皆さんはどのように解決していますか？

一昔前ならGoogle検索、最近ならLLMを使った調査が一般的ですね。

確かに、困ったことがあればLLMに聞けば解決すると言う部分も多くなりました。
LLMは非常に便利ですが、時々ハルシネーションを起こし、誤った情報をまるで正しいかのように出力することがあります。

また、技術ブログは「表面的な情報」を教えてくれますが、「なぜそのような判断になったのか」という文脈まではカバーしきれていない事が多いです。

だからこそ、 **一次情報** に直接あたるスキルが重要になります。

Goの一次情報を自分で探れるようになると、単なる「仕様」の理解にとどまりません。

Goチームが何を大切にし、何をトレードオフにしたのかという「設計思想」にまで深く触れることができるのです。

### ワークショップの進め方

1. **チュートリアルワーク:** まずは各カテゴリに用意された基本的な課題にいくつか取り組み、グループメンバーと一緒に公式ドキュメントやソースコードをたどる「調べ方のコツ」を体験します。
2. 4名程度のグループに分かれます。
3. **テーマ設定:** スタッフが班ごとに探索ワーク用のissueを用意します。調査の感覚を掴んだところで、グループごとに **「今日深く調べたいテーマ」** を設定します。残りのシナリオから興味のある難問を選んでもよいですし、日々の開発で気になっている自分たちの疑問を直接お題として設定しても構いません。
4. **探索ワーク:** 用意されたissueを使い各班は調査を進めましょう。設定したテーマについて深く探索し、答えやその背景を導き出します。なお、ヒントと解説は各問題の README に折りたたんで最初から公開しています。行き詰まったら自由に開いて構いません。「正解」を知ることよりも、「どのようにしてその情報へ辿り着くか」という調査の過程を体感することを大切にしてください。
5. **全体共有:** 終盤に、それぞれのグループが取り組んだお題について、「どうやって調べたか」「どんな発見があったか」を全体で共有します。


## ワークショップの出題問題についての説明

- **01-packages** : Goのパッケージに関する出題
- **02-features** : Goの機能に関する出題
- **03-cmd-tools** : Goのtoolに関する出題
- **04-deep-dive** : Goの歴史などGoを更に深く知りたい

各ディレクトリ内のREADME.md でそのテーマごとの主な一次情報の探し方例が記載されています。

そのREADME.mdを参考にしながら探索ワークを進めていくとよいでしょう。

## グループ分け
このワークショップでは参加者のレベルに合わせて
- 初心者(Beginner)
- 中級者(Intermediate)
- 上級者(Advanced)

の問題が用意されています。

まずは自分が解いてみたい問題のレベルにあわせて4名程度の班を作ってみましょう。

上級者が中級者や初心者向けの問題を解いてみるのも問題ないですが
逆に初心者が上級者の問題を解こうとするとワークショップの時間内に終わらない可能性があるため
レベルを上げる場合でも中級者くらいにしておいたほうが良いと思います。

会場のスタッフはレベルごとに参加者に手を上げてもらい。班を作ってもらってください。
また、分かれる班ごとにissueをを事前に作成して割り当てを行ってください。

自分のレベルが分からない？ ある程度Go歴が長いならちょっと上を目指してみても良いかも？
