# スタッフ向け運営ガイド

このドキュメントは、ワークショップを運営するスタッフ向けのガイドです。
当日は [README.md](README.md) を参加者と共有しながら、その順に沿って進行します。班には [TEAM_GUIDE.md](TEAM_GUIDE.md) も開いてもらいます。
参加者向けガイドに含めない事前準備、当日のスタッフの動き、チュートリアルのデモ台本をまとめます。

このガイドは、別のカンファレンスや勉強会でも使い回せるように、会場に依存しない手順だけを本文に書いています。
開催ごとの事情は末尾の [回ごとの実施メモ](#回ごとの実施メモ) にまとめます。開催予定の回がある場合は、本文と合わせてそちらも読んでください。

## 体制

| 役割 | 人数の目安 | 仕事 |
|:---|:---|:---|
| ファシリテーター | 1名 | [README.md](README.md) を画面共有し、台本に沿って進行・タイムキープする |
| サポートスタッフ | 2〜3班に1名 | 班分けの誘導、探索ワーク中のグループを巡回 |

最小構成は、ファシリテーター1名＋サポートスタッフ1名の計2名です。

## 事前準備（前日まで）

### 会場・設備の確認

- [ ] 参加者向け Wi-Fi があること（pkg.go.dev、GitHub、Go Playground に接続できること）。不安定な会場では、ファシリテーターの手元だけでも予備回線（テザリング等）を用意します。
- [ ] ファシリテーター用のスクリーンまたはプロジェクター。
- [ ] 発表のときに各班の PC を投影へ繋ぎ替えるか。繋ぎ替えない場合は、成果物を集める先（チャットなど）を用意して参加者へ案内します。**映像の入力端子と、必要な変換アダプタが会場にあるか** を確認します。用意がなければ持参します。
- [ ] マイクの種類（手持ち／ピンマイク）。手持ちしかない場合、チュートリアルは片手がふさがった状態で進めることになるため、画面操作と説明を分担するかを決めておきます。
- [ ] 会場に入れる時刻と、机の配置変更を主催者側で行う必要があるか。必要な場合は、設営にかかる時間を逆算して入り時刻を決めます。
- [ ] 終了後にレイアウトを戻す必要があるか。次の枠の担当者がいる場合の引き継ぎ方も確認します。
- [ ] 参加者向けの電源の有無。全員分がない場合は、募集ページで事前充電を案内します。
- [ ] 参加者がリポジトリへたどり着く経路。イベント側の資料 URL 欄に登録する場合は、**リポジトリを公開してから登録します**。公開前に反映されると、公式サイトから 404 に飛びます。
- [ ] 参加者にPC持参を事前案内していること。
- [ ] 4名程度で島を作れる机のレイアウト。
- [ ] Go Playground で Run と Share が使え、共有 URL を班の Issue に貼れること。

### 班用 Issue の作成

このワークショップは **最大7班・28名** を想定しています。
班ごとの調査ログ用 Issue を、このリポジトリに班の数だけ事前作成します（参加者数が読めない場合は7班分作っておき、余った分は当日クローズします）。

Issue の中身は Issue template [調査ログ（ワークショップ班用）](../.github/ISSUE_TEMPLATE/research-log.md) として用意してあります。
Web の「New issue」からテンプレートを選び、タイトルの「班N」を班番号に書き換えるだけで作成できます。

`gh` コマンドで7班分を一括作成する場合は次を実行します。

```bash
for n in $(seq 1 7); do
  gh issue create \
    --title "[Go探無比] 班${n} 調査ログ" \
    --body "$(sed '1,/^---$/d' .github/ISSUE_TEMPLATE/research-log.md)"
done
```

作成した Issue の URL 一覧を、当日スタッフ全員に共有しておきます（班が決まった時点で口頭・紙・チャットなどで班に渡せるように）。

### ファシリテーターのリハーサル

- [ ] 本番と同じ長さで一度通す。会場によっては当日の事前リハーサルができず、社内の通し練習が唯一の機会になります。
- [ ] [README.md](README.md) を一度通しで読み上げてみる。
- [ ] 「チュートリアルのデモ台本」（後述）を実際に操作して練習する。特に pkg.go.dev の `f` キー検索、「Printing」「Other flags」「Explicit argument indexes」の各セクションへの到達、Go Playground での実行を手に馴染ませておく。
- [ ] 投影時のブラウザ表示倍率を事前に決めておく。README の表、シナリオのコードブロック、pkg.go.dev のページ内検索ダイアログが後方の席から読めるかで判定します。決めた倍率は [回ごとの実施メモ](#回ごとの実施メモ) に残しておくと、次の開催時にそこから始められます。

## 当日の運営

### チュートリアルのデモ台本（00:05 - 00:25）

ファシリテーターは、次の操作を画面で実演します。
[fmt-printf](01-packages/01-beginner/fmt-printf/README.md) を画面共有し、次の台本に沿ってライブデモを進めます。
参加者には、fmt-printf の README と <https://pkg.go.dev/fmt> を手元で開いて同じ操作を追ってもらいます（README のチュートリアルセクションで案内済みです）。

#### 1. シナリオを確認する（2分）

[fmt-printf の README](01-packages/01-beginner/fmt-printf/README.md) を開き、シナリオのコードを見せます。

```go
fmt.Printf("%#[1]v %[1]T\n", value)
```

まず [Go Playground](https://go.dev/play/p/RTNSvn_p2Ai) で実行し、出力を全員で確認します。続けて **Share** を押し、
同じコードを URL で班へ共有できることを見せます。ローカル Go の準備が終わっていない参加者は、そのまま Playground で追えると案内します。

> 伝えること: 「先輩のコードにこの1行があったとします。`%#[1]v` って何？と思ったら、今日はググる前に公式ドキュメントを開きます」

#### 2. 設問1をライブデモで解く（8分）

<https://pkg.go.dev/fmt> を開き、次の順に操作します。

1. `f` キーを押してページ内検索ダイアログを出す（pkg.go.dev のショートカットであることを紹介する）。
2. Overview 冒頭の「Printing」セクションを開き、書式指定子（verb）の一覧表から `%v`、`%#v`、`%T` を探す。
3. 「Other flags」では `#` の効果が verb ごとに異なることを確認し、`%#v` 自体の意味は Printing の表に戻って確定する。
4. Go Playground に戻り、`value` を構造体やマップに変えて `%v` と `%#v` の出力の差を実際に確かめる。

> 伝えること: 「ドキュメントを上から全部読む必要はありません。目当ての記号やキーワードでページ内検索して、該当セクションだけ読めば十分です」

#### 3. 設問2をライブデモで解く（5分）

「引数は1つなのに、なぜ2回出力される？」という疑問を提示し、次の順に操作します。

1. <https://pkg.go.dev/fmt> の Overview で `[` を検索する。
2. 「Explicit argument indexes」セクションを読み、`[1]` が「1番目の引数を使え」という指定だと確認する。

#### 4. 調査の型をまとめる（3分）

> 伝えること: 「今やったことが、このワークショップ全体で使う調査の型です。
> (1) 公式ドキュメントを開く → (2) キーワードで該当セクションに絞る → (3) 手を動かして挙動を確かめる。
> この型のカテゴリ別の逆引きが、各カテゴリの README（例: [01-packages の調べ方](01-packages/README.md)）にまとまっています。探索ワークで困ったら、まずそこに戻ってください」

#### 5. シナリオの構成を紹介する（2分）

各シナリオの README には、ヒントと答えが `<details>`（折りたたみ）で最初から公開されていることを見せます。
答えには **調査ルート**（どの一次情報をどの順で辿るか）が書かれているので、答えを開いた場合でもルートを自分でなぞり直すことを勧めます。

### グループ分けの誘導（00:25 - 00:30）

1. ファシリテーターの案内に合わせて、「初級」「中級」「上級」ごとに挙手してもらい、人数を数えます。
2. レベルごとにエリアを指定し、移動してもらいます。
3. 各エリアで4名程度の班を作ってもらいます。端数が出たら3〜5名で調整します。
4. 班が確定したら、その場で班番号と Issue の URL を伝えます。
5. [TEAM_GUIDE.md](TEAM_GUIDE.md) を開き、短い自己紹介、調査担当、まとめ役を決めてもらいます。

### 探索ワーク中の各グループを巡回（00:35 - 01:15）

サポートスタッフは担当エリアを巡回し、次の観点で声をかけます。

- **手が止まっている班:** 「カテゴリの README（逆引き手順）は見ましたか？」とまず入り口へ誘導します。答えを直接教えるのではなく、調査ルートを示すのがこのワークショップの支援方針です。
- **シナリオで詰まっている班:** ヒント・答えの `<details>` を開いてよいことを改めて伝えます。
- **調査ログが止まっている班:** 「今どのページを見ていますか？それをそのまま Issue にコメントしましょう」と促します。
- **一人だけが操作している班:** 観測・API/仕様・実装/履歴・反例のうち未担当の仕事を選び、別の入口から並行してもらいます。
- **URL だけが並ぶ班:** 「何を確かめるために、どの検索語でその節へ着き、何が分かったか」まで追記してもらいます。
- **テーマが大きすぎて発散している班:** 「残り時間で答えられる問いに絞るなら？」と粒度の調整を助けます。

### タイムキープ

タイムキープはファシリテーターの担当です。押しがちなポイントと調整方法は次のとおりです。

| タイミング | 調整方法 |
|:---|:---|
| チュートリアルが押した | 設問2のデモを「Overview で `[` を検索すると Explicit argument indexes に着きます」の紹介だけに短縮する |
| テーマ選択が押した | [シナリオ一覧](README.md#シナリオ一覧) から選ぶことを促し、00:35 で打ち切る |
| 探索ワーク残り10分 | 全体に声をかけ、発表用まとめの記入を開始してもらう（README の「終盤の合図」） |
| 発表が長引いて収まらない | 発表を1班1分に短縮する。それでも収まらない場合はピックアップ制に切り替え、残りの班は Issue の共有をもって発表に代える |

発表時間の目安: 班数 × 1分 ＋ クロージング5分。最大想定の7班でも 7 × 1分 ＋ 5分 = 12分で、枠の15分に収まります。
<https://clock.shikakun.com/> を投影しておくと参加者も視覚的に残り時間が伝わります。

### クロージング後

## 回ごとの実施メモ

会場や運営ルールに依存する事情を、開催ごとにここへ追記します。
本文の汎用手順と切り分けておくことで、次に開催する人が「どこが会場依存で、どこが毎回同じか」を見分けられます。

### Go Conference 2026（2026-09-11 13:30-15:00 / 90分枠）

参加者は 22名（定員28名）、スタッフは3名。
以下は運営から配布されたスピーカーマニュアルに基づく、この回に固有の制約です。本文の手順に対する上書きとして扱います。

#### 会場と設営

- 会場に入れるのは開始20分前から。登壇者の集合は10分前。
- 机の配置変更は実施者が自分で行う。開始前の準備時間で島を作る必要があるため、設営役と入り時刻を事前に割り当てておく。
- 終了後は指定の基本レイアウト（ルーム2A / 2B それぞれに指定あり）へ戻す。次の枠の担当者が先に到着した場合は、前後の担当者で協力して次の希望配置へ変える。

#### 機材

- 投影は登壇者の PC から HDMI 接続。会場に変換アダプタの用意はないため、HDMI ポートのない PC を使う場合は持参する。
- 会場での事前リハーサルの時間はない。接続確認は入場後（開始20分前）に行う。
- 社内の予行はリモートで実施するため、投影とマイクの実機確認ができない。ブラウザの表示倍率は、前日に別会場で投影して決めておく。
- 確定した表示倍率: （前日の確認後に記入）
- マイクは手持ちのみ。ピンマイクの貸し出しはない。チュートリアルは画面を操作しながら話すため、片手がふさがる前提で台本を確認しておく。
- Wi-Fi は参加者向けと登壇者向けで別のネットワーク。運営から「接続が安定しないリスクもある」と案内があるため、予備回線としてモバイル Wi-Fi を 3 台貸し出し手配済み。
- 参加者全員分のコンセントは用意されない。connpass の募集ページで事前充電を案内したうえで、コンセントタップを 6 個貸し出し手配済み。

#### 進行

- 終了前の合図が会場スタッフからも入る（方法は当日案内）。README の「残り10分の声かけ」と重複しないよう、当日にすり合わせる。
- ワークショップは配信・アーカイブの対象外。
- 公式ハッシュタグは `#gocon26`。
